# Third-party audio assets

`incoming/audio/` was delivered as plain music/SFX files with no accompanying license file, readme, or attribution metadata bundled alongside them. The project owner has since confirmed the source and license terms for the two file groups actually wired into the running build (music and the `mixkit-*` SFX — see Manifest below); those rows are no longer placeholders. The two remaining unused files (`male-laugh-evil-chuckle-...`, `sad-trombone-...`) were not part of that confirmation and stay `REQUIRES_USER_CONFIRMATION` — they are also not wired into any cue and not copied into `public/audio/`, so they ship nowhere in the production build.

**Status for public release** — `AC-MEDIA-006` ("every asset is original or properly licensed") in `13_ACCEPTANCE_CRITERIA.md` now has confirmed terms for every file that actually ships. The confirmed use is **personal, private, non-commercial** per the project owner (Suno Free output), which must be respected when deciding how/where this build is deployed. The Mixkit files carry Mixkit's own free-license terms (see URL below) independent of that constraint.

## Why 3 of the 12 delivered SFX files are unused

Per the integration brief's own caution and this product's "never punish, never mock" tone rules (`01_PRODUCT_SPEC.md` §11, `BASE44_DESIGN_IMPLEMENTATION_NOTES.md` §8 forbidden copy list):

- **`sad-trombone-...`** — reads as mocking/sarcastic; this product deliberately frames every wrong answer as a learning moment ("Loop-X did exactly what you asked — try a more precise goal"), never a punchline. Kept on disk, never wired.
- **`male-laugh-evil-chuckle-...`** — a villain-gloat sting only makes sense for a specific, consistent "the villain just won a round" beat, which doesn't exist as a distinct moment in the current battle flow (every "wrong" outcome is framed the same neutral way). Kept on disk in case a future iteration adds a dedicated villain-gloat beat; not wired by default.
- **`mixkit-player-losing-or-failing-...`** — same reasoning: the app has no "you failed" state to attach it to (a wrong answer is "not yet," not a failure), so using it on `feedback` would misrepresent the product's own tone rules.

None of these three were converted or copied into `public/audio/` — they cost nothing in the shipped bundle and remain exactly as delivered in `incoming/audio/sound/`.

## What to do next

The two unused files (`male-laugh-evil-chuckle-...`, `sad-trombone-...`) are still `REQUIRES_USER_CONFIRMATION` and not wired into any cue or copied into `public/audio/`, so they don't affect the shipped build. If a future round wires either one to a new cue (e.g. a dedicated "villain gloats" moment), its license must be confirmed first — do not ship it on the strength of the mixkit-pattern filename guess alone.

Deployment reminder: the confirmed music license is **personal/private/non-commercial only**. If this build is ever deployed publicly (a public URL, a competition submission judged/played by third parties, app-store distribution, etc.), re-confirm with the project owner whether that still satisfies the license, or swap the music tracks for assets with a public-release-compatible license before shipping.
